## Порядок выкладки

Порядок важен: приложение без таблицы не падает (вкладка «Деньги» объясняет, что делать), но API и календарь надо выкладывать вместе с миграцией.

1. **Миграция.** Применить `supabase/migrations/0011_subscriptions.sql` к проекту (`apply_migration` или редактор SQL в панели Supabase). Она ничего не удаляет и не меняет существующие таблицы.
2. **Права токена агента.** Выдать токену `claude-funnel-sync` новые права:
   ```sql
   update agent_client set scopes = scopes || array['subscriptions:read', 'subscriptions:write']
   where name = 'claude-funnel-sync' and not scopes @> array['subscriptions:write'];
   ```
3. **Edge Functions.** Выложить `ingest` (новые маршруты), `calendar` (списания, файл `billing.ts` рядом) и `notify` (адрес перехода пуша). У `ingest` и `calendar` `verify_jwt = false`, как и раньше.
4. **Боевой смоук.** `python tools/api_smoke.py`: 20 проверок вместо 13. Тестовую подписку и вакансию удалить SQL, как написано в шапке скрипта.
5. **Приложение.** `git push` в `main`: GitHub Actions соберёт и выложит PWA. Перед этим тесты в CI (`npx vitest run`) пройдут сами.
6. **Агент.** Добавить шаг в `funnel-sync` (текст ниже) и проверить один прогон.

## Шаг для задачи funnel-sync

> **3b. Подписки.** Только если `python "D:/Пульт Германа/tools/pult.py" get subscriptions` отвечает без ошибки (иначе пропусти шаг и напиши в сводке «подписки: нет доступа»).
> В письмах за прошедшие сутки найди чеки, квитанции и уведомления о продлении или скором списании (слова «подписка», «продление», «списание», «receipt», «renew», «trial»). Для каждого сервиса: название, сумма, валюта, период, дата ближайшего списания, ссылка на управление.
> Перед записью прочитай `get subscriptions` и сверь по названию, чтобы не заводить дубли. Запись: `put subscriptions/<ключ-латиницей> body.json`, поля `name`, `amount`, `currency`, `unit`, `every`, `nextChargeOn`, `status` (`trial`, если это пробный период), `category`, `method` (название карты или последние цифры, номер карты не писать), `url`.
> Не меняй и не возвращай то, что поставил Герман: API отклоняет такие правки сам. В сводке одной строкой: сколько подписок добавлено или обновлено.

## Откат

Если нужно вернуться, миграция откатывается так (данные подписок будут потеряны):

```sql
select cron.unschedule('queue-charge-reminders');
drop function if exists private.queue_charge_reminders();
drop function if exists private.next_charge(date, text, integer, date);
drop table if exists public.subscription_reminder;
drop table if exists public.subscription;
update agent_client set scopes = array_remove(array_remove(scopes, 'subscriptions:read'), 'subscriptions:write');
```

Приложение откатывается обычным откатом коммита в `main` (деплой Actions сработает заново). Старые адреса вкладок `#more` и `#stats` в новой версии ведут на «Настройки» и «Цифры».

## Открытые вопросы

- Задача `pult-ask-claude` в Claude на ПК запускается вручную, расписания у неё нет. Ответы на «Спросить Claude» и поиск подписок в почте приходят, когда её запустили. Расписание (например, каждые 30 минут днём) тратит лимиты, решать Герману.
- История списаний («оплачено») не ведётся: приложение показывает будущие списания, а не факт оплаты. Можно добавить, когда понадобятся расходы за прошлые месяцы.
- Валюты не пересчитываются по курсу (ADR-006).
