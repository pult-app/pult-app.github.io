# ADR-003. Агенты пишут через отдельный ingest API с токенами

- Статус: принято
- Дата: 27.09.2026

## Контекст

Данные в пульт приносят ИИ-агенты: задачи Claude Code по расписанию. Агенты читают чужой текст (письма, страницы hh.ru), значит, возможна prompt injection. В v0 агент писал в базу страницы claude.ai от имени владельца, и 26.09.2026 этот доступ пропадал примерно на час.

## Варианты

| Вариант | Риск |
| --- | --- |
| Дать агентам ключ `service_role` и Data API | Ключ обходит RLS и даёт полный доступ, включая удаление. Утечка ключа из промпта или логов агента означает потерю всех данных |
| Завести агенту учётную запись пользователя | Агент может всё, что может Герман, и нельзя разделить права разных задач (почта, поиск вакансий, расписание) |
| Отдельная Edge Function `ingest` с токенами агентов | Нужно написать и поддерживать API |

## Решение

Отдельный API `ingest` по [OpenAPI](../05-api/openapi.yaml):

- у каждого агента свой токен, в базе только SHA-256, срок 180 дней, отзыв флагом;
- права на уровне операций (`messages:write`, `vacancies:write` и так далее);
- в API нет методов удаления и отправки чего-либо наружу;
- строгие схемы: неизвестные поля и превышение длины дают 422;
- идемпотентность через `PUT` по естественному ключу и `Idempotency-Key` для `POST`;
- `If-Match` на изменение вакансии, чтобы агент не затёр ручную правку Германа (412);
- агент не возвращает вакансию на более ранний этап (422 `status-downgrade`);
- журнал запусков `sync_run`.

## Последствия

- Взломанный или обманутый агент может только добавить или поправить записи, удалить ничего не может. Ошибку видно в журнале запусков, откат делает Герман в интерфейсе.
- Ключ `service_role` есть только у Edge Functions в секретах Supabase.
- Скилл `mail-triage` и задачу `funnel-sync` нужно перевести с ArtifactData на этот API (этап миграции в MVP).
