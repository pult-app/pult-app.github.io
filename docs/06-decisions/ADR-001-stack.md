# ADR-001. Стек: React, Vite и Supabase

- Статус: принято
- Дата: 27.09.2026

## Контекст

Нужно личное PWA с базой, входом, серверными функциями и пушами. Бюджет 0 ₽. Код пишут ИИ-агенты, поэтому важны распространённые технологии с хорошей документацией. Я знаю SQL и PostgreSQL (курсовая «БД для аптеки», MS SQL и PostgreSQL на 2 курсе) и должен уметь объяснить архитектуру на собеседовании.

## Варианты

| Вариант | Плюсы | Минусы |
| --- | --- | --- |
| React + Vite + Supabase | Postgres, RLS и SQL, которые я могу защитить. Auth, API и функции из коробки. Бесплатный тариф покрывает нагрузку одного пользователя | Бесплатный проект засыпает после недели простоя, нет бэкапов и своего домена |
| Next.js + Firebase (идея июля 2026) | Офлайн и синхронизация в Firestore из коробки | NoSQL: модель данных и ограничения на стороне кода, хуже ложится на мой опыт SQL |
| Next.js + Supabase | Один стек с сайтом-портфолио | Серверный рендеринг не нужен личному PWA, развёртывание сложнее |

## Решение

React, Vite и TypeScript на клиенте (vite-plugin-pwa для манифеста и service worker). Supabase на сервере: PostgreSQL, Auth, Data API (PostgREST), Edge Functions, pg_cron, pg_net.

## Последствия

- Бизнес-правила, которые нельзя обойти (история статусов, очередь пушей, уникальность), живут в базе: триггеры и ограничения.
- Три ограничения бесплатного тарифа закрыты процессом: агенты пишут в базу 3 раза в день (нет паузы), еженедельная выгрузка на диск (нет бэкапов), фронтенд на своём поддомене (домен Supabase не виден пользователю).
- Схема и API не привязаны к облаку Supabase. Если сервис станет недоступен из РФ, можно поднять Supabase в Docker на VPS.
