# ADR-004. Расписание хранится снимком JSON, пары считает клиент

- Статус: принято
- Дата: 27.09.2026

## Контекст

Расписание группы приходит из проекта ЛАД одним JSON: 6 дней, по 7 слотов для числителя и знаменателя. В каждой ячейке строка вида «111-3, лб, Иванов И.И., Базы данных (с 9 по 15 нед)», подгруппы разделены переводом строки. Расписание меняется несколько раз за семестр.

## Варианты

| Вариант | Плюсы | Минусы |
| --- | --- | --- |
| Нормализовать в таблицы `lesson`, `room`, `teacher` | Можно делать SQL-запросы по парам | Дублируем парсер ЛАД, при каждом обновлении нужна пересборка таблиц, для одного пользователя запросов по парам нет |
| Хранить снимок JSON, пары считает клиент | Одна запись на версию расписания, работает офлайн, логика та же, что в ЛАД | Разбор строки ячейки на клиенте |

## Решение

Таблица `schedule_snapshot`: группа, хэш источника, момент выгрузки, `payload jsonb`, флаг текущего снимка. Новый хэш создаёт новый снимок, одинаковый хэш ничего не меняет. PWA считает неделю и пары по правилам ЛАД:

- числитель: учебная неделя, в которую попадает 1 сентября;
- номер недели считается от понедельника этой недели, первая неделя имеет номер 1;
- пара активна, если неделя попадает в диапазон «(с X по Y нед)», «(с X нед)», «(по Y нед)».

## Последствия

- Логика уже проверена в v0 на реальном расписании ПИ-124: 26.09.2026 это 4-я неделя (знаменатель), 28.09.2026 это 5-я неделя (числитель).
- Старые снимки остаются для истории. Видно, когда и что поменялось в расписании.
- Если в v2.0 понадобится расписание многих групп, снимки масштабируются по `group_code` без изменения схемы.
