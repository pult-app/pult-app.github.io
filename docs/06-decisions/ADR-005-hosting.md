# ADR-005. Хостинг: GitHub Pages отдельной организации

- Статус: принято
- Дата: 27.09.2026

## Контекст

Пульт это отдельный продукт, он не должен быть частью сайта-портфолио. Аккаунт GitHub, где живёт портфолио, раздаёт все свои проектные страницы под доменом портфолио: страница репозитория `pult` открылась бы как `<домен портфолио>/pult/`. Бюджет 0 ₽, приложение должно открываться из России без VPN.

Проверка 27.09.2026 по открытым источникам: Vercel в РФ блокируется частично (зависит от IP), Netlify блокируется полностью, у Cloudflare Pages провайдеры режут общий домен `pages.dev`. GitHub Pages открывается: на нём уже работает сайт-портфолио.

## Варианты

| Вариант | Доступ из РФ | Цена | Отдельность от портфолио |
| --- | --- | --- | --- |
| Pages текущего аккаунта | есть | 0 | нет, адрес под доменом портфолио |
| Vercel, Netlify | нестабильно или нет | 0 | да |
| Свой домен + Pages | есть | домен платный | да |
| Pages отдельной организации GitHub | есть | 0 | да |

## Решение

Бесплатная организация GitHub `pult-app`, репозиторий переносится в неё. Адрес продукта `https://pult-app.github.io/` (если репозиторий назван `pult-app.github.io`) или `https://pult-app.github.io/pult/`. Путь задаётся переменной `PULT_BASE` при сборке, код от него не зависит.

## Последствия

- Когда появится свой домен, он подключается к Pages организации через файл `CNAME` без изменений в коде.
- В Supabase Auth в Site URL и Redirect URLs прописывается адрес продукта.
- Организацию создают только через сайт GitHub, API для этого нет.
