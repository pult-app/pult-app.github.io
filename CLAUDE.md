# Пульт Германа (PWA)

Claude Code читает этот файл автоматически. Обзор и документы: @README.md

## Команды (проверены по README)
- Тесты приложения и контракта API: `cd app && npx vitest run`
- Сборка: `cd app && npm run build`
- Проверка схемы БД: команды `psql` из раздела «Как проверить схему базы» в README.md

## Порядок работы над фичей
Для фичи больше одного-двух файлов действует цепочка Anthropic «каждый этап кончается файлом» (скилл `intent-spec-plan`). Файлы лежат в `docs/intents/ГГГГ-ММ-ДД-<slug>/`, шаблон `docs/intents/_template.md`.
1. `intent.md`: интервью с Германом, его словами, без решений. Неясное в «Открытые вопросы». Герман читает и правит, только потом дальше.
2. `spec.md`: требования и дизайн (архитектура) из intent, спорные места и противоречия отдельным списком. Решение, которое меняет архитектуру, оформляется ещё и новым ADR в `docs/06-decisions/`, PRD (`docs/01-prd.md`) обновляется.
3. `plan.md`: в шапке ссылка на intent; разделы «Файлы», «Порядок», «Риски», «Проверка» (каждая проверка доказывает пункт intent). Перед сохранением ответить: что это может сломать, какой шаг самый рискованный, что отброшено и почему. Реализация после одобрения плана Германом.
4. Реализация в чистой сессии по plan.md. Отошёл от плана, обнови plan.md в том же коммите.
5. Готово = тесты зелёные, сборка проходит, по разделу «Проверка» отчёт пункт за пунктом с фактическим выводом, плюс сверка с каждым пунктом intent.md: выполнено или нет и где это видно.
Если новая просьба по ходу работы противоречит intent.md, остановиться и сказать об этом, а не молча выполнять.

## Рамки
- Репозиторий публичный: никаких секретов, токенов и личных данных в коммитах. `app/.env.local` в .gitignore, так и оставить.
- Агентам не давать ключ базы и методы удаления (см. README, «Безопасность»).
- Деплой идёт через GitHub Actions на pult-app.github.io: пуш в main = выкладка, поэтому изменения через ветку и PR.
